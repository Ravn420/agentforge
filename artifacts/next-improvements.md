# AgentForge — next product improvements

1. **Carry the words after a slash command into the tool.** `/research`, `/brainstorm`, and `/crew` currently switch screens and throw away everything typed after the command, so the question or topic has to be entered twice. The composer is the main way in; if the rest of the line becomes the research question, brainstorm topic, or mission seed, people start the job they already described.

2. **Let a research brief keep going instead of ending as a static dump.** A person should be able to ask a follow-up that still sees the plan and sources, and tap any plan step to expand just that step with the same citations. A brief only changes the next decision if the user can dig into the weak part without starting over from a blank box.

3. **Turn the Spark → Lens → Devil → Quill round into a choice, then a revision.** Show who shaped each of Quill’s three ideas, let the user pick one and send it into chat or a research brief, and run one more pass so Spark and Quill answer Devil’s objection before the cards freeze. Right now the crew talks once and the ideas are read-only, so the roundtable never lands a direction anyone acts on.

4. **Make Project, Slides, Swarm, and Files actually produce different work.** Slides should return a deck outline, Swarm a split of who does what, and Files a proposed structure — not the same Grok chat with a different empty-state sentence. Those four tabs are the home screen’s promise; if they all dump into one generic reply, the modes are labels, not products.

5. **Run Crew Missions as real jobs, not prompt starters.** Feature build, Bug hunt, and Docs sprint should launch a short multi-role result for the mission the user names, using crews suited to that job rather than pasting “Plan a feature build mission for:” into the home composer. That screen is the clearest offer of multi-agent work in the app, and today it only fills the chat box.

6. **Keep chats, briefs, and brainstorm rooms in the sidebar so a Guest can reopen them.** Each run should be a named item the user can jump back to, and a chosen idea or brief should stay attached when they move between Chat, Research, and Brainstorm. The session is local and everything disappears when the view changes or the page refreshes, so research and crew work cannot compound.
